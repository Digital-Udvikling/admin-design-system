## Examples

### Basic

:::example

```html
<div class="menu">
  <button type="button" class="menu-trigger" popovertarget="menu-basic">Open menu</button>
  <div class="menu-popup" id="menu-basic" popover>
    <button class="menu-item" type="button">
      <i class="ti ti-pencil" aria-hidden="true"></i>
      Edit
    </button>
    <button class="menu-item" type="button">
      <i class="ti ti-copy" aria-hidden="true"></i>
      Duplicate
    </button>
    <hr class="menu-separator" />
    <button class="menu-item menu-item-danger" type="button">
      <i class="ti ti-trash" aria-hidden="true"></i>
      Delete
    </button>
  </div>
</div>
```

```tsx
<Menu>
  <Menu.Trigger>Open menu</Menu.Trigger>
  <Menu.Popup>
    <Menu.Item icon={IconPencil}>Edit</Menu.Item>
    <Menu.Item icon={IconCopy}>Duplicate</Menu.Item>
    <Menu.Separator />
    <Menu.Item icon={IconTrash} danger>
      Delete
    </Menu.Item>
  </Menu.Popup>
</Menu>
```

### Checkbox and radio items

In vanilla, checkable rows are native checkboxes and radios in a `<label class="menu-item">`.

:::example

```html
<div class="menu">
  <button type="button" class="menu-trigger" popovertarget="menu-view">View</button>
  <div class="menu-popup" id="menu-view" popover>
    <label class="menu-item">
      <input type="checkbox" class="checkbox" name="grid" checked />
      Show grid
    </label>
    <label class="menu-item">
      <input type="checkbox" class="checkbox" name="ruler" />
      Show ruler
    </label>
    <hr class="menu-separator" />
    <div class="menu-group" role="group" aria-labelledby="view-density">
      <div class="menu-group-label" id="view-density">Density</div>
      <label class="menu-item">
        <input type="radio" class="radio" name="density" value="comfortable" checked />
        Comfortable
      </label>
      <label class="menu-item">
        <input type="radio" class="radio" name="density" value="compact" />
        Compact
      </label>
    </div>
  </div>
</div>
```

```tsx
<Menu>
  <Menu.Trigger>View</Menu.Trigger>
  <Menu.Popup>
    <Menu.Item defaultChecked>Show grid</Menu.Item>
    <Menu.Item defaultChecked={false}>Show ruler</Menu.Item>
    <Menu.Separator />
    <Menu.RadioGroup defaultValue="comfortable">
      <Menu.GroupLabel>Density</Menu.GroupLabel>
      <Menu.RadioItem value="comfortable">Comfortable</Menu.RadioItem>
      <Menu.RadioItem value="compact">Compact</Menu.RadioItem>
    </Menu.RadioGroup>
  </Menu.Popup>
</Menu>
```

### Filter menu

A GET form around the rows submits the choice without JS, and `menu-actions` holds its buttons. In React, use checkable `Menu.Item`s and apply the choice from your own state.

:::example

```html
<form class="menu" method="get">
  <button type="button" class="menu-trigger btn" popovertarget="menu-status-filter">Status</button>
  <div class="menu-popup" id="menu-status-filter" popover>
    <label class="menu-item">
      <input type="checkbox" class="checkbox" name="status" value="open" checked />
      Open
    </label>
    <label class="menu-item">
      <input type="checkbox" class="checkbox" name="status" value="pending" checked />
      Pending
    </label>
    <label class="menu-item">
      <input type="checkbox" class="checkbox" name="status" value="closed" />
      Closed
    </label>
    <hr class="menu-separator" />
    <div class="menu-actions">
      <button type="reset" class="btn btn-ghost btn-sm">Reset</button>
      <button type="submit" class="btn btn-primary btn-sm">Apply</button>
    </div>
  </div>
</form>
```

The menu is a [Base UI Menu](https://base-ui.com/react/components/menu): arrow keys move between items, typing jumps to a matching item, Escape and a click outside close it, and focus returns to the trigger.

`variant` styles the trigger as a [Button](../buttons/) of that variant, square when it has no children; `size` applies only alongside it. `icon` renders a leading icon; with `variant` and no children the trigger is an icon-only square without the chevron, so give it an `aria-label`.

The popup portals into the enclosing [`AdminRoot`](../../getting-started/react/), or into a `Dialog` it sits in. Its items stay mounted while it is closed, so `hotkey` works with the menu closed. A `Dialog` or `Drawer` that an item opens goes outside `<Menu>`, driven by the item's `onClick`; one rendered inside the popup is hidden with it. For a confirmation, use [`useConfirm()`](../dialog/).

`href` on an item renders a real `<a>`, so right-click "open in new tab" and copy-URL work, and `render` renders the link item onto your own element, such as a router link (see [Conventions › `render`](../../basics/conventions/#render)); without either the item is a `<button>`. Disable a button item with the native `disabled` attribute and an anchor item with `aria-disabled="true"`, since an `<a>` has no `disabled`. Both dim and stop activating, hotkeys included.

`checked` or `defaultChecked` makes an item checkable (`menuitemcheckbox`) with a leading check; `false` still reserves the gutter, so labels stay aligned down the group. For single-select, put `Menu.RadioItem`s in a `Menu.RadioGroup`, which takes its name from a `Menu.GroupLabel` inside it like `Menu.Group`.

`hotkey` dispatches a click on the item and right-pins a [Kbd](../kbd/) chip, on both the button and anchor branches. See [Conventions › Hotkeys](../../basics/conventions/#hotkeys).

For a form value, use a [Select](../forms/selects/).

### Vanilla

| Class                   | Effect                                                                                                                                                           |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `menu`                  | Wrapper around the trigger and popup; scopes the anchor name                                                                                                     |
| `menu-trigger`          | Trigger `<button>`: pointer cursor, trailing chevron that rotates while the popup is open                                                                        |
| `menu-popup`            | Popup panel on a `[popover]`: `11rem` min-width (the trigger's width when wider), `20rem` max-width, `18rem` max-height, scrolls, bordered surface with a shadow |
| `menu-popup-end`        | Aligns the popup to the trigger's end edge                                                                                                                       |
| `menu-item`             | Row: full width, `0.75rem`/`0.25rem` padding, `text-sm` on a `1.25rem` line, hover wash, inset focus ring, `0.5rem` gap for an icon, checkbox or radio           |
| `menu-item-danger`      | Destructive item: danger label and icon, danger-tinted hover                                                                                                     |
| `menu-item-indicator`   | `1em` check gutter, always reserved; its glyph shows only when `aria-checked="true"`                                                                             |
| `[aria-current="page"]` | On `menu-item`: primary-muted fill, primary text, medium weight                                                                                                  |
| `menu-separator`        | `1px` divider with `0.25rem` of margin                                                                                                                           |
| `menu-group`            | Column wrapper for a labelled set                                                                                                                                |
| `menu-group-label`      | Group heading: `text-xs` uppercase, muted                                                                                                                        |
| `menu-actions`          | Right-aligned button row, for a filter menu's Reset and Apply                                                                                                    |

The popup is a `popover="auto"` element opened by the trigger's `popovertarget`, which needs a unique `id` per menu. The browser opens and closes it: Escape and a click outside close it, and it renders in the top layer, so a `<dialog>` or an `overflow: hidden` ancestor doesn't clip it. It is anchored to the trigger inside its `.menu` and flips above the trigger, or to its end edge, when there's no room.

The vanilla menu is a disclosure: a button that shows a list of links and buttons, reached with Tab, with no menu roles and no arrow-key navigation. Give a `menu-group` `role="group"` and `aria-labelledby` pointing at its `menu-group-label`. A link item navigates; a button item leaves the popup open unless it opens a modal `<dialog>` (via `commandfor`), which closes it, or it carries `popovertarget="<id>" popovertargetaction="hide"`. Checkable rows are native checkboxes and radios inside a `<label class="menu-item">`; `menu-item-indicator` is for rows your own script marks with `aria-checked`. A disabled anchor item takes `aria-disabled="true"` and no `href`, so neither a click nor Enter navigates.

`menu-trigger` only styles behaviour and bows out of appearance when a `btn` class is present, so adding `btn btn-primary` to the trigger gives a button-styled trigger with no override needed. An empty trigger centres its chevron, as the split-button pattern does — pair it with an `aria-label`, since the chevron is the only visible content. A `btn-square` trigger that holds an icon drops the chevron and needs an `aria-label` too. A `menu` inside a [`btn-group`](../buttons/#group) joins the strip's rounding and seams.
